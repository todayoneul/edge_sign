# README 재구성 — 평가 대응 정직한 리프레이밍 설계

> **상태:** 승인됨 (2026-06-06). Stage 1(재구성) 즉시 실행 → Stage 2(why 분석) 후속.

## 배경

교수/연구자 관점 두 건의 혹평을 받았다. 공통 지적:
1. **연구 기여 불분명** — "인식기가 가장 양자화 민감"은 너무 당연한 결론.
2. **Phase 1(ConvNeXt) 장황·연결 약함** — 프록시 태스크(Recall@K 검색)가 다운스트림(검출/OCR)과 종이 달라 기법 전이 보장 0.
3. **"왜 망가지는가" 분석 부재** — 관찰만, 메커니즘 없음.
4. 1-Bit 죽은 가지, LLM Q&A 약함, "Edge" 과장(실디바이스 미측정), MOTA 0.295 절대값 낮음, README 과길.

## 핵심 통찰 (리프레임의 축)

진짜 기여는 "인식기가 민감"(당연)이 아니라 **반직관적·실측 전용 발견 2가지**:
1. 백본에선 무손실인 INT8이 YOLO **검출 헤드(DFL)** 에선 붕괴 — CosSim 0.9995가 은폐(방법론 교훈).
2. 엣지 런타임에서 **"저정밀 = 고속"이 거짓** — INT8 ConvInteger 오버헤드, WebGPU FP32 > FP16.

→ 논지 전환: **"양자화 민감도는 기법이 아니라 아키텍처·런타임에 의존한다."**
이러면 Phase 1(깨끗한 분류기)은 **대조군**으로 의미가 생긴다: 백본에선 우아하게 degrade·SmoothQuant 승 → 파이프라인에선 이야기 역전. 그리고 이게 Phase 12(YOLO26 DFL 제거)로 자연 연결된다.

## 결정 사항

- **분석 깊이: 단계적.** Stage 1 = 정직한 재구성(즉시 제출 안전). Stage 2 = why 정량 분석 후속.
- **Phase 1: 대조군으로 압축.** 본문에 짧은 "대조군" 섹션 + 표 1개, 상세는 부록. ConvNeXt 변호 삭제 → "다른 태스크라 전이 안 됨"을 *역으로* 대조 논거로.

## Stage 1 작업 (이번)

평가 약점 1:1 대응:
- **최상단 TL;DR 신설** — 문제·논지(아키텍처·런타임 의존)·반직관 대표결과 3개·데모 링크. (README 과길 + 기여 묻힘 대응)
- **개요/연구질문 논지 전환** — 반직관 발견을 전면, "인식기 민감"은 3개 중 하나로 격하.
- **§3 Phase 1 → 대조군 압축** — 변호 문단 제거, 전이 비보장을 대조 논거화.
- **§8 매몰 발견 승격** — DFL 붕괴·INT8≠고속을 TL;DR로 끌어올림(본문 §8은 유지).
- **정직성 라인** — Q&A "프레젠테이션 레이어, 기여 아님" 명시 / MOTA 0.295 절대값 맥락 / "Edge"=브라우저·WASM·WebGPU 런타임으로 정밀 한정(Jetson/Pi 미측정 명시).
- **1-Bit** 한 줄 압축 유지.

## Stage 2 작업 (후속, why 정량 분석)

- **DFL 헤드 INT8 붕괴 메커니즘** — v3(YOLOv8s) 헤드 vs 백본 레이어별 활성화 동적범위/outlier, 헤드 양자화 시 분포-bin 로짓의 softmax-기대값 왜곡 → bbox 회귀 붕괴 정량화(SQNR 또는 검출수·conf).
- **OCR W4A16 붕괴 메커니즘** — 레이어별 활성화 outlier(max/median, kurtosis) → 4-bit 표현력 한계·SmoothQuant 정당화.
- 결과를 README 새 "§ 붕괴 원인 분석"과 `docs/EXPERIMENTS.md`에 기록.

## 비범위 (YAGNI)

- YOLO26/폰은 Future Work 유지(별도 트랙, 학습 중).
