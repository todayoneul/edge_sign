# Edge-Sign Phase 12 — "Precision Ladder on Edge" 설계

> 작성일: 2026-06-06 · 브랜치: `feat/precision-ladder-edge`
> 목적: 경진대회/포트폴리오용 **라이브 데모**의 서사를 명확히 하고, 기존 양자화 연구 자산을
> 폰 온디바이스 + 데스크톱 정밀도 사다리로 무대화한다. 새 라벨링 없이 기존 데이터/모델을 재학습·재사용한다.

---

## 1. 배경 & 문제

기존 프로젝트(Edge-Sign Phase 1~11)는 **검출+추적+인식 파이프라인의 단계별 양자화 민감도**라는
연구적 깊이를 이미 갖췄다(E0~E7 매트릭스, Pareto, 민감도 히트맵, 온디바이스 WebGPU 스파이크, Q&A).

그러나 **시연의 메시지가 약하다**: 화면에 박스가 그려지고 추적되는 그림은 다른 학생들의 단순
객체검출 데모와 겉보기에 동일하다. 이 프로젝트의 진짜 무기(양자화 민감도, 엣지 압축, "어느 단계가
먼저 깨지는가")가 한눈에 드러나지 않는다.

**목표:** 모델을 화려하게 바꾸는 것이 아니라, *무엇을 보여줄 것인가(시연 서사)*를 먼저 정하고
그 서사를 받쳐주는 수단으로 최신 모델(YOLO26)과 폰 온디바이스 실행을 도입한다.

---

## 2. 한 줄 서사 (데모가 증명하는 것)

> "우리는 *어느 단계가 양자화에 먼저 깨지는지*를 연구로 밝혔다(DFL 검출 헤드 = INT8 병목,
> Phase 11). **YOLO26**은 바로 그 병목(DFL·NMS)을 구조적으로 제거했다. 그래서 이제
> **end-to-end로 양자화해 폰에서 실시간으로 돌리고**, 그 정밀도 사다리를 한 화면에서 *눈으로* 보여준다."

이 서사는 **연구 발견 → 최신 모델 → 엣지 배포**를 한 줄로 꿰며, 단순 검출+추적 데모와 차별화된다.

---

## 3. 범위 (In / Out)

**In scope**
- 검출기를 YOLO26-n으로 재학습(기존 `data/yolo_signs_v2/`, 2클래스). 실패 시 YOLO11-n 폴백.
- 검출기 4개 정밀도 변형 export: FP32 / FP16 / INT8(static QDQ) / W4A16(fake-quant).
- 폰 온디바이스(WebGPU) 경로: 검출+추적+한국어 인식 라이브 + FP32⇄FP16 토글 + HUD.
- 데스크톱 콘솔: "정밀도 사다리" + 정밀도별 인식 붕괴 시각화 + DFL 비교 패널 + B-1 오버레이 + 기존 Q&A.
- B-1: 사전학습 주행영역/차선 모델 **추론만**(학습 0), 서버 추론, 주간 클립.
- 90초 시연 스크립트 + 샘플 클립 + 반응형 레이아웃.

**Out of scope (YAGNI)**
- 주행영역/차선 **학습**(B-2 의사라벨 증류) — 마감 리스크로 제외, 후속 과제.
- 표지판 OBB(B-3) — 제외.
- 폰에서 seg/4정밀도 전부 실행(옵션 2) — 발열/메모리 리스크로 제외.
- 서버 GPU 의존 폰 뷰어(옵션 3) — "온디바이스 엣지" 서사 약화로 제외.
- 새 데이터 라벨링.

## 4. 아키텍처 (역할 분담 — 옵션 1)

```
┌─ 폰 (온디바이스, WebGPU) ──── "엣지 증명" ──────────┐
│  카메라/클립 → YOLO26-n(fp16) → ByteTrack-TS →      │
│  KoreanSignNet(fp16) → 박스+한국어 라벨 라이브       │
│  토글: FP32 ⇄ FP16 · HUD: FPS / 모델크기 / EP        │
└──────────────────────────────────────────────────┘
┌─ 데스크톱 콘솔 (web_modern) ── "연구 쇼케이스" ──────┐
│  ① 정밀도 사다리: FP32(WebGPU)→FP16(WebGPU)          │
│       →INT8(WASM)→W4A16(WASM) — 각 런타임 매핑 표기   │
│  ② 붕괴 시각화: 같은 프레임, 정밀도별 박스+한국어     │
│       라벨 나란히 → W4A16 인식 붕괴(깨진 한글) 강조    │
│  ③ DFL 패널: "v8 헤드는 FP32 고정 → YOLO26 풀-INT8"  │
│  ④ 주행영역/차선 오버레이(B-1, 사전학습 추론)         │
│  ⑤ Q&A (기존 Groq LLM)                               │
└──────────────────────────────────────────────────┘
```

- **단일 코드베이스**(`web_modern`), 반응형으로 폰/데스크톱 분기. 폰=집중 서브셋, 데스크톱=풀 랩.
- **검출기 모델 비종속 레이어**: 입출력 인터페이스를 고정해 YOLO26 ↔ YOLO11-n 폴백이 컴포넌트
  변경 없이 가능하도록 한다(`clientPipeline.ts`의 디코드/후처리를 모델 메타로 파라미터화).

## 6. 데이터 & 학습 계획

- **검출기 재학습**: 기존 `data/yolo_signs_v2/`(2클래스: `0=traffic_sign`, `1=traffic_light`) 그대로
  사용 → YOLO26-n 학습. **새 라벨링 불필요.** 학습 설정은 v3(`edge_sign_v3_lights`) 관행 계승
  (imgsz·patience·close_mosaic), 단 모델만 YOLO26-n.
- **정밀도 변형 생성**:
  - FP32 ONNX (기준)
  - FP16 ONNX (WebGPU용, 기존 `export_fp16_detector.py` 패턴 계승)
  - INT8 static QDQ (WASM/CPU용, 기존 `quantize_v3_detector.py` 패턴). **YOLO26은 DFL이 없으므로
    헤드 포함 풀-INT8 실험을 수행**하고, 실프레임 검출 수/conf로 검증(EXPERIMENTS.md 신규 행).
  - W4A16 fake-quant (붕괴 시연용).
- **인식기**: 기존 `korean_sign_net_fp32.onnx`(14클래스) 유지 + fp16 변형. 붕괴 시연의 주인공은
  인식기 W4A16(기존 발견: OCR Top-1 −43.9pp). 인식기는 새로 학습하지 않는다.
- **B-1 주행영역/차선**: 사전학습 모델(예: YOLOP 계열 panoptic driving) **추론만**, 학습 0.
  한국 야간 도메인갭을 피하기 위해 **주간 클립**에 적용.

## 7. "정밀도 사다리"의 정직한 런타임 매핑 (핵심 기술 포인트)

| 정밀도 | 실행 런타임 | 어디서 | 의미 |
|---|---|---|---|
| FP32 | WebGPU | 폰·데스크톱 | 기준 |
| FP16 | WebGPU | 폰·데스크톱 | 크기 절반, 폰 실시간 |
| INT8 (QDQ) | WASM/CPU | 데스크톱 | WebGPU INT8 미지원 → 런타임이 바뀜을 *그대로 보여줌* |
| W4A16 | WASM (fake-quant) | 데스크톱 | 인식 붕괴 시연 |

> 근거: 브라우저 온디바이스 스파이크 실측 — FP32/WebGPU 62FPS 가능, **INT8은 WebGPU 불가** →
> fp16 방향. 따라서 "정밀도를 낮추면 *런타임 자체가 바뀐다*"는 현실을 숨기지 않고 무대화하는 것이
> 단순 토글보다 정직하고 수준 높다.

## 8. 빌드 단계

- **P1 (먼저, 디리스킹)**: YOLO26 → ONNX → ORT-Web WebGPU 스파이크 검증.
  성공 → YOLO26 채택, 실패 → YOLO11-n 폴백 확정. **이후 모든 단계는 이 결정 위에서 진행.**
- **P2**: 검출기 재학습 + 4정밀도 변형 export + 측정(EXPERIMENTS 확장, 풀-INT8 헤드 실험 행 추가).
- **P3**: 폰 온디바이스 경로(YOLO26 fp16 + ByteTrack + KoreanSignNet + FP32/FP16 토글 + HUD)
  → **실제 폰 실측**(FPS/발열/메모리).
- **P4**: 데스크톱 정밀도 사다리(PerfStrip 확장) + 정밀도별 붕괴 시각화 + DFL 비교 패널.
- **P5**: B-1 주행영역/차선 오버레이(서버 추론) + 토글.
- **P6**: 데모 폴리시 — 90초 시연 스크립트, 샘플 클립, 반응형 레이아웃, Q&A 연결.

## 10. 검증 전략

- **추적**: 기존 골든 ByteTrack 테스트(`scripts/export_bytetrack_golden.py` fixture) 재사용.
- **변형 패리티**: 기존 `tests/test_pipeline_variants.py` 확장(정밀도 변형 로드/전환/stage_ms).
- **정밀도별 검출 패리티**: **실프레임 박스/conf로 검증**(Phase 11 교훈: 전체 텐서 CosSim은 검출
  붕괴를 못 잡으므로 금지). 실프레임 검출 수·conf 비교.
- **폰 FPS**: 기존 스파이크 하니스(`public/spike/`)로 실측.
- **게이트**: `web_modern` `npm run build`·`vitest` · `ruff`/`mypy src/pipeline` · `pytest tests/`.

## 11. 90초 시연 흐름

1. **폰 라이브**: 카메라/클립 → 박스+한국어 라벨 추적. FP32→FP16 토글 → FPS↑·모델크기↓.
   *"서버 없이, 이 폰에서 진짜 돈다."*
2. **데스크톱 사다리**: 같은 영상, 정밀도 사다리. INT8→W4A16로 내리면 검출은 버티지만
   **한국어 인식이 깨진 한글로 붕괴**. *"압축은 공짜가 아니다 — 어디서 깨지는지 우리는 측정했다."*
3. **DFL 패널**: *"YOLOv8 헤드는 INT8에서 무너졌다(우리 발견). YOLO26은 그 헤드를 없앴다.
   그래서 이제 end-to-end로 양자화한다."*
4. **마무리**: 주행영역 오버레이 ON + 어시스턴트에게 "지금 운전 상황?" → LLM 자연어 답변.
