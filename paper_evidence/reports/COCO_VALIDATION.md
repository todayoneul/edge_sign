## 2. 정확도 (ORT CPU, pycocotools)

유지율은 FP32 대비 mAP@0.5:0.95이다. 신뢰구간은 이미지 단위 부트스트랩 1,000회(seed 0)로 구했다. pycocotools의 누적 계산을 이미지 가중치로 다시 구현했고, 가중치가 1일 때 공식 값과 같음을 확인하였다.

- **FP32 기준값:** 0.5401로, MLPerf 참조값 53.4(Ultralytics 공식, COCO val 전체)에 가깝다. 부분집합과 평가 코드가 달라 약간의 차이는 예상된다.
- **MLPerf 절대 목표(참고):** yolo-99 = 52.87, yolo-95 = 50.73이다. 헤드 제외(53.56)와 디코드 제외(53.47)는 우리 평가 코드 기준으로 두 목표를 모두 넘는다. 공식 평가 코드와 달라 판정에는 쓰지 않는다.
- **출력 연결 텐서의 양자화 파라미터:** INT8 전체 모델에서 척도 2.7709, 영점 12, 범위 −33.25–673.34이다. 점수 1.0은 0.36 단계에 불과해 영점으로 반올림된다.

- 사용자에게 iCloud Drive를 일시정지하도록 요청했지만, 측정 중에 배경 프로세스가 코어 1개 정도를 쓴 구간이 두 번 있었다.
  - `vgtray` 17:25–17:32: CPU 4T의 FP32·FP16·INT8 전체와 겹침
  - iCloud Drive 17:58–18:06: WASM 4T FP32와 겹침
- 이 네 측정은 결과와 무관하게 부하 기록만을 기준으로, 부하가 가라앉을 때까지 기다린 뒤 다시 측정하였다(`scripts/paper/wait_quiet.ps1`: 측정과 무관한 프로세스가 3% 미만인 표본이 3회 연속; 부하 기록은 `scripts/paper/cpu_sampler.ps1`).

  - 처음 측정값: `runtime/matrix/coco_bgload/`
  - 처음 값과 재측정값의 차이는 10% 이내였다(CPU 4T FP32 182.1 → 180.9, FP16 182.9 → 191.7, INT8 전체 77.1 → 85.7, WASM 4T FP32 733.4 → 762.7 ms).
