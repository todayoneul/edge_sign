# 구성요소 × 정밀도 × 실행 환경 양자화 매트릭스 (2026-09-25, 2026-09-26 보강)

논문 주제 「도로 영상 인식을 위한 브라우저 기반 엣지 비전의 구성요소·실행 환경별 양자화 실증 분석」에 필요한 근거를 한 번에 측정한 결과다. 질문은 세 가지다.

1. **구성요소 민감도**: 같은 양자화 설정에서 검출기의 백본·넥, 검출 헤드, 인식기 가운데 어디가 정확도를 잃는가?
2. **실행 환경 의존성**: 같은 ONNX 파일이 네이티브 CPU, 브라우저 WASM, 브라우저 WebGPU에서 얼마나 빠른가? 양자화의 이득이 실행 환경마다 뒤집히는가?
3. **구성요소별 배치**: 검출기와 인식기를 각각 다른 실행 환경에 둘 때 파이프라인 지연이 어떻게 달라지는가?

## 1. 실험 설계

### 1.1 요인

| 요인 | 수준 |
|---|---|
| 구성요소 | 검출기 YOLO26-n(v4, 출력 [1,300,6], NMS 불필요), 검출기 YOLOv8s(v3, 출력 [1,6,8400], DFL 헤드 + NMS), 인식기 KoreanSignNet(14-class, 입력 32×32) |
| 정밀도 | FP32, FP16, INT8 static QDQ |
| INT8 양자화 범위 | 전체 그래프(full) / 마지막 모듈 FP32 유지(head-excluded). 검출기 헤드 = 마지막 `model.N`, 인식기 헤드 = 분류 conv `/fc2_conv/Conv` |
| INT8 bias 표현 | INT32(ORT 기본) / FP32(`QuantizeBias=False`) |
| 실행 환경 | ORT CPU 1.23.2(1·4 스레드), ORT-Web 1.30.0 WASM(1·4 스레드), ORT-Web WebGPU 1.30.0·1.22.0 |

INT8 설정은 모든 변형에서 같다: per-channel 대칭 INT8 가중치, 비대칭 UINT8 활성값, MinMax 캘리브레이션, `quant_pre_process` 후 `quantize_static`(QDQ).
- 검출기 캘리브레이션: `paper_evidence/splits/calibration_manifest.jsonl`(validation 150프레임).
- 인식기 캘리브레이션: `paper_evidence/splits/recognition_calibration_manifest.jsonl`(`data/roi_cls/val`에서 seed 0으로 뽑은 ROI 512개). 두 캘리브레이션 모두 독립 test 프레임을 쓰지 않는다.
- 새로 만든 변형과 해시는 `paper_evidence/models/quantize_variants_log.json`(검출기), `recognizer_variants_log.json`(인식기)에 있다.
- 기존 파일(`yolo_v4_signs_int8_static.onnx`, `yolo_v4_signs_int8_head_excluded.onnx`, `yolov8s_signs_v3_int8_static.onnx`)은 덮어쓰지 않았다.

### 1.2 측정 방법

**정확도**
- 검출기: 독립 test 2,417프레임, COCO 방식 mAP@0.5:0.95와 mAP@0.5(`evaluate_qdq_detection.compute_metrics`).
- 인식기: 같은 test의 수동 GT 박스에서 자른 ROI 6,771개의 Top-1(`recognizer_variants.py evaluate`).
- 유지율은 같은 계열 FP32 대비 비율이다.
- 디코딩은 모든 변형에 똑같이 적용했다.
  - v4: 출력을 그대로 사용한다(conf ≥ 0.001).
  - v3: argmax 클래스, conf ≥ 0.001, 클래스별 NMS IoU 0.7, 최대 300개.

**지연**
- 배치 1, 고정 프레임 하나, warm-up 20회 뒤 1,024회를 측정했다(MLPerf 단일 스트림 p90 요건).
- 추론 호출만 잰다. 입력 텐서 생성 시간은 `prepare_ms`로 따로 기록했다.
- 예외: WebGPU INT8은 호출 한 번이 약 1초라서 warm-up 5회와 측정 128회만 했다. 이 행의 p90은 참고치다.

**입력 동일성**
- 모든 실행 환경이 같은 입력을 받는다. 서버가 cv2로 640×640(인식기 32×32) RGB uint8을 만들고, 각 실행 환경은 정규화만 한다.
- 따라서 정확도 차이는 전처리가 아니라 커널 차이에서 나온다.

**연산자 배치**
- ORT-Web을 verbose로 실행해 `VerifyEachNodeIsAssignedToAnEp` 로그를 파싱했다(`placement.json`).
- 파싱 조건: 모든 EP에서 "배치된 노드 수 = 나열된 노드 수"일 때만 완전한 로그로 인정한다.

**브라우저 파이프라인** (`browser_pipeline.html`)
- 한 페이지에서 검출기와 인식기 세션을 각자 지정한 EP로 만든다.
- 프레임마다 다음 순서로 처리하고 단계별 시간을 기록한다: 정규화 → 검출 → 디코딩(conf ≥ 0.25) → ROI 자르기(8% 여백, bilinear 32×32) → 인식(검출 수만큼 배치).
- 조건: test 앞쪽 512프레임을 순서대로 처리했고 warm-up은 20프레임이다.
- 프레임 fetch(카메라 입력에 해당), 추적기, 화면 렌더는 제외한다.

**통제**
- 측정은 한 번에 하나씩 순차 실행했다.
- Chrome은 실행마다 새 임시 프로필로 headless(`--headless=new --enable-unsafe-webgpu`) 실행했다.
- WASM 4스레드는 COOP/COEP 헤더로 `crossOriginIsolated=true`를 만든 서버에서만 가능하다. 결과 JSON에 `cross_origin_isolated`와 적용 스레드 수를 기록했다.

### 1.4 판정 기준 ([EVALUATION_CRITERIA.md](EVALUATION_CRITERIA.md))
- 정확도: FP32 대비 주 지표 99% 이상 유지(MLPerf Inference, 사전 기준). 95%는 현행 MLPerf YOLO 과제(`yolo-95`)와 비교하기 위한 참고 등급으로만 함께 적는다(2026-09-26 추가).
- 지연: 기준 A는 p90 ≤ 33.3 ms(30 FPS), 기준 B는 p90 ≤ 66.7 ms(15 FPS). 지연표의 A/B 표시는 검출기 단독 추론에 대한 판정이다. 파이프라인은 실행당 512프레임 × 5회이므로 실행별 p90의 중앙값으로 판정하고, 5회를 합친 2,560프레임의 p90으로 같은 판정인지 확인한다(2.5절).

- **v3의 가중치 손실은 DFL 고정 커널에서 나온다.**

  - YOLOv8s 헤드에는 DFL 기대값을 계산하는 고정 1×1 커널(값 0–15)이 있다. 이 커널 하나만 FP32로 두면 유지율이 96.37%에서 **99.60%**로 돌아온다.
  - 이 커널은 학습 가중치가 아니라 적분 계산식이다. 채널별 INT8 격자(간격 15/127)로 반올림하면 각 bin의 위치값이 최대 0.055 bin 어긋나고, 박스 좌표에 계통 오차가 생긴다.
  - YOLO26-n에는 이 커널이 없어 가중치 전용 양자화의 손실이 1% 안팎이다.

## 4. 한계
- **기기와 브라우저:** Windows 데스크톱(RTX 5070)과 Mac(M2 Pro) 두 대, Chrome 153 headless에서만 측정했다(2.6절). Safari·Firefox·모바일은 측정하지 않았다. 측정 절차는 [DEVICE_MEASUREMENT_GUIDE.md](DEVICE_MEASUREMENT_GUIDE.md)에 있다.
- **데이터:** 같은 AI Hub 수집원의 시퀀스 독립 분할 하나이다. test의 야간 프레임은 16장뿐이다.
- **파이프라인 측정 범위:** 추적기(가중치 없음, JS ByteTrack), 캔버스 렌더, 카메라·영상 디코딩을 포함하지 않는다.
- **부트스트랩 신뢰구간:** 프레임 부트스트랩은 프레임 간 상관을 무시하므로 실제보다 좁다. 25프레임(5초) 이동 블록 부트스트랩을 함께 보고한다(`bootstrap_retention.json`의 `block`).
- **단일 텐서 검사:** test 242프레임의 선별 검사이다. 결론에 쓴 붕괴(출력 연결 텐서)와 필요성(붕괴 텐서 제외)은 test 전체로 다시 확인하였다.
- **실행 간 편차:** 파이프라인 반복 측정은 배경 부하(클라우드 동기화)가 있는 상태에서 이루어졌다. 절대 지연보다 같은 회차 짝 비교를 우선한다.
- **WebGPU INT8 표본:** 128회 측정이라 p90은 참고치다.
